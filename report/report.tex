\section{System and command flow}
This project completes the course detector and adds command-triggered visual grounding to the provided TurtleBot3 navigation framework. Gazebo simulates the room, robot, camera, and laser scanner. ROS 2 nodes process those sensor messages, build a map, interpret a command, and coordinate Nav2 navigation. Gazebo itself does not interpret the language command.

A user publishes a string to \code{/user\_command}, for example \emph{Move to the red chair.} The coordinator pauses exploration, cancels conflicting navigation, waits for Nav2 to become idle, and forwards the command. A launch parameter selects exactly one target-selection mode. Both modes reuse the same target message, approach-pose adapter, coordinator, and Nav2 backend.

\textbf{Baseline selection.} The deterministic parser recognizes configured categories, aliases such as ``trash can,'' and an optional index such as \code{person\_2}. Without an index, it selects the nearest matching landmark relative to the robot's current map position. An index selects that exact observed memory ID. IDs reflect observation order, not personal identity. The parser does not model color: both red-chair and blue-chair descriptions reduce to category \code{chair}. This source-level fact does not predetermine the result of a live baseline run.

\textbf{Visual detection.} The completed loading method loads the course's tracked \code{tb3det\_yolo26n.pt} once; \code{infer()} returns label, confidence, and pixel bounding box in the wrapper's existing format. The current configured classes are \code{person}, \code{trash\_can}, and \code{chair}, with the supplied 0.40 threshold preserved. The ROS wrapper continues publishing its existing detection and debug-image topics. Before editing, a direct test on a blank $480\times640$ image emitted the stub warning, with \code{is\_loaded=False} and no detections; the full stub stack was not launched.

\section{From image pixels to a navigation goal}
\textbf{Two different maps.} SLAM Toolbox uses laser scans and robot motion to estimate pose and construct an occupancy grid: cells indicate free, occupied, or unknown space. Semantic memory adds labeled object landmarks such as \code{person\_2}. It associates repeated detections and retains map positions. Occupancy mapping answers ``where can the robot move?''; semantic memory answers ``which observed object is this?'' A label alone is neither an obstacle map nor a safe navigation goal.

\textbf{LocateAnything insertion.} In LocateAnything mode, the baseline query node is not launched. A persistent worker in a separate Python environment loads the existing local LocateAnything-3B model. The complete referring expression is preserved: only the leading movement phrase is removed. For the red command the actual prompt was:
\begin{quote}\small
Locate a single instance that matches the following description: the red chair.
\end{quote}
The model's selected box, rather than a later category lookup, determines the specific target. Continuous YOLO detections may continue updating ordinary semantic memory, but cannot replace this selected instance. Each selection has its own \code{locateanything\_N} ID.

\textbf{Coherent geometry.} Grounding waits for a stationary robot and captures an actual camera image, CameraInfo, a nearby laser scan, odometry, and timestamped transforms. The sensor matching tolerance is 0.15~s; stale images and motion during inference are rejected. Transforms are captured before the slower inference finishes. An old observation is never restamped with the inference-completion time.

Model coordinates use a 0--1000 scale. They are converted to the original $W\times H$ camera pixels by $u=xW/1000$, $v=yH/1000$. For box center $(u_c,v_c)$ and camera intrinsics, the optical ray is
\[
\mathbf r_c=\big((u_c-c_x)/f_x,\;(v_c-c_y)/f_y,\;1\big).
\]
The camera-to-scan rotation gives a planar bearing $\theta$. Nearby valid laser returns inside the box's angular width provide a median range $d$. The scan-frame point $(d\cos\theta,d\sin\theta,0)$ is transformed into \code{map} using the saved scan-time TF. This reuses the research localizer's planar approximation; it assumes the requested object intersects the laser plane and ignores the small camera-to-laser translation when forming the ray.

\textbf{Navigation.} The selected metric point is sent directly in \code{SemanticQueryResult}. The adapter computes a 0.5~m standoff along the current robot-to-target direction in the same frame. Nav2 uses the occupancy map, costmaps, and localization to plan and execute the approach. The coordinator tracks success/failure and automatically re-enables exploration after a delay. In the mapped chair demonstration, exploration nodes are intentionally disabled; the observed ``exploration resumed'' status is a coordinator state transition, not an exploration-motion test.

\textbf{Failure behavior.} Empty or malformed output, multiple boxes, stale/mismatched sensors, robot motion, unusable laser returns, missing TF, and inference errors produce a clear failure and no new target goal. There is no fallback to another chair. The message's \code{confidence=1.0} is a documented transport placeholder, not calibrated model confidence.

\textbf{Selection and localization evidence.} Both commands reached the model with their color description, produced one box around the requested chair, and preserved that instance through navigation. The selected map coordinates were $(0.858,0.727)$ for red and $(0.776,-0.691)$ for blue. Source image-to-scan offsets were 94~ms and 10~ms. Selected-point discrepancies from the Gazebo chair origins were 0.339~m and 0.434~m. These include the difference between the observed near surface and the model origin; they are not direct estimates of sensor accuracy.

\textbf{Arrival measurement.} A \code{TARGET\_REACHED} message alone does not establish course acceptance. After the terminal transition and before resumed motion, the evaluator queries the actual robot and object world poses. The final planar distance to the intended object is compared with the course's unchanged 1.2~m criterion. The distance to the other chair was 1.623~m for the red run and 1.648~m for the blue run. Gazebo object poses are used only by this evaluator, never by grounding, target selection, or goal generation.

\textbf{Interpretation.} Four earlier attempts also passed; all six records are retained. The latest pair confirms that concurrent baseline detections did not overwrite the grounded instance after the final integration fix. These repeated implementation checks cover two example commands, not a success-rate benchmark. The latest blue result has only 0.030~m margin under the threshold.

\section{Validation status, contributions, and limits}
\label{sec:contributions}
\textbf{Completed checks.} All nine packages build; 40 focused tests and an isolated ROS action cancellation regression pass. The live detector self-test passed. Generic \code{go to person} reached the center person at 0.702~m. Commands for observed IDs \code{person\_0} and \code{person\_1} reached northwest and southeast people at 0.672~m and 0.688~m. The corrected trash-can run passed at 0.726~m. Exploration resumed after each successful baseline run.

\textbf{Chair limitation.} Unaided exploration for 600~s left the chair mislabeled as a trash can, and \code{go to chair} failed with no chair landmark. After an ordinary memory-based reposition command, an operator turned the camera toward the chair and held still for 22~s. The unchanged detector/memory then relabeled it; a new chair command reached the correct chair at 0.973~m and exploration resumed. This assisted navigation pass does \emph{not} establish the unaided chair acceptance criterion. No GT goal coordinates, injected landmarks, or threshold changes were used.

\textbf{Retained failure evidence.} The live baseline color comparison failed for both red and blue commands with ``no active chair in memory''. The recolored red chair was detected as a person, yielding a false person landmark and no selectable chair. Thus the measured contrast includes detector/memory errors on altered appearances; it is not a controlled test of language parsing alone. Separately, the source parser discards color. The blue evaluator also logged an unavailable map TF, preserved in the record.

The first generic-person attempt had missing Gazebo pose queries; its failed evaluator verdict and supplemental 0.751~m measurement are both retained. The first trash-can command selected a mislabeled chair and stopped 2.096~m from the intended trash can. A retry selected the right region but aborted (2.090~m). Waiting for cancellation acknowledgement and Nav2 idle fixed that handoff race; the later trash-can run passed. All attempts, setup notes, and observer errors remain in \code{results.json}.

\textbf{My additions.} I completed the detector's two required methods; added the persistent model worker, original-image box parser, stationary synchronized capture, and exact-instance map bridge; added mutually exclusive baseline/LocateAnything modes and two chair material variants; and made bounded backend corrections for robot-relative map selection/standoff, command handling, cancellation, and asynchronous result ordering. The supplied ROS topics and baseline detector return contract are retained. No model training, new planner, or full-room language search was added.

\textbf{Scope and reproduction.} Validation uses Ubuntu 22.04, ROS 2 Humble, an RTX 5090, PyTorch 2.7.1+cu128, Ultralytics 8.4.60, and NumPy 1.26.4. The extension is limited to static, mapped scenes with visible targets that the laser can localize. It does not establish reliable absent-target rejection or arbitrary attribute/relation grounding. README contains the actual launch, reset, and display commands. The final 2--4 minute video is to be recorded manually by the student; no video has been created or linked here.
